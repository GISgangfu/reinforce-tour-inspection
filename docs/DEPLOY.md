# 安全巡检视频处理 · 对外发布指南

让**别人在自己电脑上打开你的平台**，分三个层次。请按需要选，不要跳级。

| 层次 | 谁可以访问 | 需要什么 | 安全风险 |
|---|---|---|---|
| A. 局域网共享 | 同一 WiFi/公司内网的同事 | 改一个启动参数 | 低（需访问码） |
| B. 公网临时分享 | 任何人（凭链接+访问码） | 隧道工具，约 5 分钟 | 中（地址公开，需访问码） |
| C. 公网长期部署 | 任何人 | 一台云服务器 + 域名 | 需按生产标准加固 |

## ⚠️ 先读这一条：本平台不是普通展示页

本平台包含**设备指令接口**：OTA 固件升级、远程重启、触发实时画面、修改设备命名与绑定。

这意味着：

- **一旦上公网，任何拿到链接的人都能给你的设备下发指令。**
- 所以「能上公网」的前提是「能拦住人」。平台已内置**访问码**机制（见下），
  但它的安全等级只相当于"一个足够长的口令"，适合给同事看一眼，
  **不适合承载真实生产设备**。

**结论**：层次 A 可以直接用；层次 B 请务必设置访问码并只在演示期开启；
层次 C 必须加账号体系、操作审计、设备指令二次确认。

## A. 局域网共享（最简单，先试这个）

服务默认只监听本机，同事访问不到。改成监听所有网卡即可：

```
serve-forever.cmd 8899
```

然后按启动横幅提示操作。监听 `0.0.0.0` 后启动横幅会直接打印可分享的链接，形如：

```
本机访问   http://127.0.0.1:8899
局域网访问 http://192.168.0.45:8899

── 访问控制已启用 ─────────────────────────
访问码     a1b2c3d4e5f6...
分享链接   http://192.168.0.45:8899/?token=a1b2c3d4e5f6...
```

**把「分享链接」整条发给同事**，他在自己电脑浏览器打开即可。
首次打开会带上访问码，平台随即把它换成 Cookie，之后刷新不需要再带码。

### 两个前提

1. **同事要在同一个局域网**（同一个 WiFi、或公司内网）。手机热点也行。
2. **Windows 防火墙要放行**。第一次启动时如果弹出"是否允许 Node.js 通信"，
   勾选**专用网络**并允许。如果没弹窗或误点了拒绝，需要手动放行
   （需要管理员权限，会弹 UAC）：

   ```powershell
   # 以管理员身份运行 PowerShell 后执行
   netsh advfirewall firewall add rule name="安全巡检视频处理 8899" dir=in action=allow protocol=TCP localport=8899
   ```

   删除这条规则：

   ```powershell
   netsh advfirewall firewall delete rule name="安全巡检视频处理 8899"
   ```

> 说明：我无法在当前环境验证防火墙放行是否成功——`netsh advfirewall` 查询需要管理员权限，
> 实测返回 "requires elevation"。所以这一步请你自己确认；如果同事打不开，
> 九成是防火墙没放行。

### 你的内网地址

当前探测到的是 `192.168.0.45`（WLAN 网卡）。换网络后会变，
以**启动横幅打印的地址为准**，不要记死。

## B. 公网临时分享（用隧道，不动路由器）

多数家庭宽带**没有公网 IP**，且运营商封禁 80/443 端口，所以端口映射通常行不通。
隧道工具用"出站连接"把本机服务映射到一个公网地址，不需要公网 IP、不需要动路由器。

### 方案一：Cloudflare Tunnel（推荐，免费、自动 HTTPS）

**第 1 步** 下载客户端（约 53 MB）：

```
node scripts\get-cloudflared.mjs
```

若因网络问题失败，脚本会给出镜像源与手动下载说明。
下载完成后文件位于 `tools\bin\cloudflared.exe`。

**第 2 步** 启动隧道（保持服务已在运行）：

```
node scripts\tunnel.mjs
```

控制台会打印一个形如 `https://xxxx-yyyy.trycloudflare.com` 的地址，
**把它连同访问码一起发给对方**：

```
https://xxxx-yyyy.trycloudflare.com/?token=你的访问码
```

注意事项：

- **这个地址是临时的**，隧道关闭即失效，每次重启都会变。适合演示、评审。
- 免费版**没有 SLA**，偶尔会慢或不稳。
- 想要固定域名，需要有自己的域名并托管到 Cloudflare（免费套餐即可），
  改用 `cloudflared tunnel create` 的命名隧道方式。

### 方案二：ngrok

适合不想装 Cloudflare 的场景，但需要注册账号拿 authtoken：

```
winget install ngrok.ngrok
ngrok config add-authtoken <你的 token>
ngrok http 8899
```

免费版地址同样是随机的，且每月有流量与连接数限制。

### 方案三：frp（需要一台有公网 IP 的服务器）

适合已经有云服务器的场景，可控性最好，但要自己编译/配置 frps 与 frpc。
本指南不展开。

## C. 公网长期部署（真正上线才需要）

如果这个平台要给多个项目、多人长期使用，隧道方案不合适。需要：

1. **一台云服务器**（2C4G 起步；视频转码建议 4C8G 以上）
2. **域名 + HTTPS**（用 Caddy 或 Nginx + Let's Encrypt 自动证书）
3. **把服务改成对外安全形态**：
   - 绑定 `127.0.0.1`，由反向代理转发（不要直接暴露 Node 端口）
   - 关闭 `demo-rule` 适配器，接入真实视觉模型
   - **加账号体系**：SSO / 企业微信扫码 / 至少是带用户表的登录
   - **设备指令二次确认 + 操作审计**：OTA、重启这类动作必须留痕并可追责
   - 数据落库（当前是内存 + JSON 文件，重启即丢）
4. **对象存储 + CDN** 承载视频与证据片段（不要用本机磁盘对外提供视频）

## 关于访问码（平台内置的防护）

### 怎么设置

优先级：命令行 `--token` > 环境变量 `YZX_TOKEN`。

```
node server/index.mjs --host 0.0.0.0 --token 你的访问码
```

### 平台会自动兜底

只要**监听地址不是本机**（即真的对外了），而你又没提供访问码，
平台会**自动生成一个 32 位随机访问码并打印在启动横幅上**——
宁可让你抄一次，也不会让设备指令接口裸奔。

访问码短于 8 位会**直接拒绝启动**。

### 怎么传给对方

三种方式任选，平台都支持：

| 方式 | 用法 | 适用 |
|---|---|---|
| URL 参数 | `https://xxx/?token=码` | 分享链接，最方便 |
| 输入框 | 打开首页，在登录页输入 | 不想把码写在链接里 |
| 请求头 | `x-yzx-token: 码` | 脚本 / API 调用 |

通过 URL 参数验证成功后，平台会下发 `HttpOnly` Cookie（12 小时有效），
所以**刷新页面、点内部导航都不会再暴露访问码**。

### 安全边界（务必理解）

- 访问码是**明文口令**，长度足够时（≥16 位随机）能挡住扫描与猜测。
- 但通过 URL 分享时，**访问码会出现在对方的浏览器历史、以及任何中间代理的日志里**。
- **不要在访问码有效期内把链接发到公开群**。演示结束后请更换访问码（重启服务并换 `--token`）。
- 当前没有"按用户区分权限"，也没有操作审计。**所有拿到访问码的人权限相同，都能下发设备指令。**

## 自检清单（上线前逐条确认）

```
# 1. 服务是否正常
node scripts\serve.mjs --status

# 2. 17 项完整体检
node scripts\doctor.mjs 8899

# 3. 访问控制是否生效（用真实端口与访问码）
node scripts\test-auth.mjs 8899 你的访问码
```

`test-auth.mjs` 会验证 16 项，包括最关键的两条：

- 无凭据访问**设备指令接口**必须被拒绝（HTTP 401）
- 有凭据时才可用

如果这两条不通过，**绝对不要挂到公网**。
